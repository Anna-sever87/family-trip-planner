# Библиотека промптов

Промпт задаёт модели роль, границы и формат ответа. В приложении он собирается из постоянных правил, анкеты и подготовленных данных. Программные проверки дополняют промпты: текстовая инструкция сама по себе не обеспечивает контроль бюджета, координат и доступа.

## Сценарии

| Тип | Назначение | Источник |
| --- | --- | --- |
| Семейная и взрослая поездка | Учитывать состав группы, время, уникальность мест и формат | `prompts.py` |
| Анкета | Передать направление, даты, группу и доступный бюджет программы | `prompts.py` |
| Региональные кандидаты | Предложить конкретные базы и места для последующей проверки | `candidate_grounding.py` |
| Городские названия | Дополнить набор реальными названиями без выдуманных цен и координат | `city_candidates.py` |
| Предпочтения и память | Ранжировать полный резерв в стандартной анкете с памятью; отдельно отбирать ID для особых текущих пожеланий | `city_preferences.py` |
| Региональное модельное расписание | Построить программу по проверенным кандидатам в соответствующей ветке | `grounded_schedule.py` |
| Городское модельное расписание | Использовать только переданные ID при выключенном серверном расписании | `city_schedule.py`, `city_quality.py` |
| Общая правка дня | Изменить только выбранный объект дня | `prompts.py` |
| Городская правка | Использовать сохранённые допустимые кандидаты | `city_edit_service.py` |
| Смысловой аудит | Проверить, выполнено ли пожелание по существу | `prompts.py` |
| Исправление замечаний | Передать конкретные ошибки валидаторов на ограниченную повторную попытку | `planner.py` |
| Обложка | Сформировать компактный текст для генерации иллюстрации направления | `cover_prompts.py` |

Эти двенадцать типов не означают двенадцать обращений к ИИ на каждую поездку. Ветки условны. При серверном расписании модель не назначает время и даты; часть запросов пропускается при достаточных исходных данных или отсутствии дополнительных предпочтений.

## Разделение инструкций и данных

Системная часть задаёт правила. Пользовательская часть содержит анкету, разрешённые места, погоду и память. Эти блоки рассматриваются как недоверенные данные, а не новые команды. JSON-схема ограничивает форму ответа; сервер проверяет его смысловые и числовые свойства.

Текущая анкета важнее прежней памяти. Модель не вправе самостоятельно присвоить месту статус подтверждения, заменить серверные координаты или объявить свободные дни.

Стандартная обзорная анкета без памяти обходится без модельного отбора. При наличии памяти модель определяет только приоритет: пропущенные ID остаются в проверенном резерве. При нестандартной цели или текущих текстовых ограничениях используется смысловой отбор, без такого дополнения. Обязательные условия пользователь указывает в текущей анкете; история не считается гарантией их выполнения.

## Бюджет

```text
Бюджет программы = общий бюджет − дорога на всю группу − жильё за все ночи.
```

Например, 60 000 − 10 000 − 15 000 = 35 000 рублей на программу. Это иллюстрация формулы, не запись личной поездки. Фиксированные расходы не прибавляются к пунктам повторно.

## Промпт изображения

В поле `prompt` Yandex Cloud Images отправляется `provider_prompt` длиной до 500 символов. В него входят направление, страна, конкретная достопримечательность и наземная композиция; возраст детей, бюджет и личные заметки не передаются. Даты участвуют в контексте и ключе кэша, но не выдаются за прогноз погоды. Для направления вне каталога сюжет выбирается из подтверждённых посещений маршрута; если подходящего объекта нет, платная генерация не запускается. Само название объекта не гарантирует точности нарисованного фасада.

Длинный английский `COVER_SYSTEM_PROMPT` — внутренняя спецификация и часть ключа кэша, а не текст текущего запроса провайдеру. Результат обозначается как ИИ-иллюстрация, а не фотография места.

## Проверка и полные тексты

Изменение промпта требует проверки затронутых сценариев: анкеты, семейных правил, разрешённых ID, границ правки и структуры JSON. Автономные тесты используют смоделированные ответы, а качество внешней модели проверяется отдельно.

- [Авторская библиотека Word](submission/prompt-library.docx) содержит назначения, входы, результаты и дословные примеры.
- [Полные тексты и составные блоки](submission/full-prompts.txt) содержат 23 извлечённые записи с указанием источников.
- [Защищённый автономный прогон](../tools/run_offline_checks.py) запрещает реальные сетевые операции и чтение секретного `.env`.

Авторские документы сохраняют примеры для защиты; актуальные исполняемые инструкции находятся в указанных исходных файлах. Это не история переписки при разработке и не доказательство того, что все перечисленные запросы выполняются в каждом сценарии.
